# Compilers Project 2 — Announcement
## Code Generation Phase

> Based on inquiries from a number of students, this clarifies the project mechanism and its input/output files.

---

## First: How the Project Works

We have two phases working together:
1) Processing data and Python instructions (Flask).
2) Processing Jinja templates and generating HTML pages.

---

## Second: General Diagram

```text
        app.py (Flask file)
              ↓
        Python Parser
              ↓
          Python AST
              ↓
      Semantic Analysis
              ↓
           Generator
              ↓
  Context Data (variables & values generated)
              ↓
       render_template()
              ↓
         Jinja File
              ↓
         Jinja Parser
              ↓
          Jinja AST
              ↓
 Variable Substitution {{ name }} {{ age }}
              ↓
             HTML
              ↓
          Browser
```

**In short:**
- Python → Bytecode → Execution
- Jinja → AST → HTML

---

## Third: Input Files

The compiler will receive three types of files:

### 1) The Backend File: `app.py`
Example:
```python
products = [
    {"name": "Phone", "price": 300},
    {"name": "Laptop", "price": 800}
]
```

### 2) Jinja Files Inside the `templates/` Folder
- `index.jinja`
- `add_product.jinja`
- `edit_product.jinja`

Example:
```jinja
{% for product in products %}
<h3>{{ product.name }}</h3>
{% endfor %}
```

### 3) Interface Design & Styling Files
- `style.css`
- `script.js` (optional)

---

## Fourth: Output Files Generated by Code Generation

**The actual output produced by the Translator:**
```text
output/
├── index.html          ← generated
├── add_product.html    ← generated
└── edit_product.html   ← generated
```

**Companion files copied to the run folder:**
- `app.py`
- `style.css`
- `script.js`

**Additionally, the following analysis/generation artifacts must be placed in a separate folder:**
```text
compiler_output/
├── ast_python.json
├── ast_jinja.json
├── semantic_report.txt
└── generation_log.txt
```

> **Note:** The files produced by the generation phase are the ones the compiler outputs directly after processing Jinja instructions and binding them to data extracted from Python.
>
> As for `app.py`, `style.css`, and `script.js`, they are support files for running the application; they are not part of the analysis or generation process, so they are kept as-is and attached to the final output without any additional processing.

---

## Fifth: Important Points (to Avoid Confusion)

- During the generation phase, only the part of Python responsible for preparing data is executed, then the values are passed to the Jinja template to generate HTML pages.
- The Symbol Table is **not** used during the generation phase; it belongs exclusively to the semantic analysis and error-checking phase.
- Any change to the interface (e.g., adding a product) requires re-generation (render) so that the output stays in sync with the data.
